Use this systematic approach when decomposing epics into
actionable work items for agile development teams.

Input Requirements:
- Epic title and business objective statement
- Target completion timeline (sprint cycles or weeks)
- Team composition and skill sets available
- Existing system constraints or technical dependencies

Step 1: Define Strategic Objective

Document the epic's core purpose using this template:
- Business Goal: [Specific user/business value to be
delivered]
- Success Metrics: [Quantifiable outcomes that indicate
completion]
- Product Vision Alignment: [How this epic advances the
overall product strategy]

Step 2: Identify Major Components (2-3 Sub-Objectives)

For each component, specify:
- Component Name: [Clear, action-oriented label]
- Purpose Statement: [One sentence describing its function
within the epic]
- Completion Criteria: [Observable outcomes indicating this
component is done]
- Estimated Effort: [Story points, hours, or sprint
allocation]

Step 3: Generate Actionable Subtasks (3 per Sub-Objective)

Each subtask must include:
- Task Description: [Specific action using format "As a
[role], I will [action] so that [outcome]"]
- Acceptance Criteria: [2-3 testable conditions for
completion]
- Priority Classification:
- High: Blocks other work or delivers core user value
- Medium: Enhances functionality but not blocking
- Low: Nice-to-have improvements or optimizations
- Effort Estimate: [Time or complexity rating]
- Required Skills: [Technical or domain expertise needed]

Step 4: Dependency & Risk Analysis

Create dependency matrix showing:
- Prerequisite Tasks: [What must complete before this task can
start]
- Blocking Relationships: [What this task enables once
completed]
- External Dependencies: [Third-party integrations, approvals,
or resources needed]
- Risk Assessment: [Technical, timeline, or resource risks
with mitigation plans]

Step 5: Execution Planning

Generate prioritized task sequence including:
- Sprint 1 Targets: [Highest priority tasks establishing
foundation]
- Critical Path: [Task sequence determining minimum timeline]
- Parallel Work Streams: [Tasks that can execute
simultaneously]
- Review Gates: [Points requiring stakeholder approval or
technical validation]

Deliverable Format:
- Epic breakdown document with all sections completed
- Dependency diagram showing task relationships
- Sprint planning recommendations with effort estimates
- Risk register with identified mitigation strategies
